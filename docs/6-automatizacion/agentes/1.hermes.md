## Hermes

**Hermes Agent** es uno de los desarrollos de software libre más revolucionarios del ecosistema de inteligencia artificial en 2026, desarrollado por [Nous Research](https://hermes-agent.nousresearch.com) como un "agente auto-evolutivo" que corre de forma persistente y local, aprendiendo de cada interacción y creando sus propias habilidades a lo largo del tiempo. Hermes funciona como un servicio persistente (daemon) diseñado para ejecutarse de forma continua, acumulando experiencia, auto-generando habilidades y adaptándose al usuario a lo largo de múltiples interacciones.

**Temas clave:**
1. **Aprendizaje y auto-evolución continua (Self-Evolving Skills):** Hermes no solo ejecuta tareas, sino que cuando resuelve un problema complejo, codifica la solución en un documento de habilidad reusable (`skills`) que queda guardado para siempre bajo el estándar abierto `agentskills.io`.

2. **Memoria persistente entre sesiones:** El agente mantiene una base de datos SQLite local (`MEMORY.md` y `USER.md`) que acumula información sobre los proyectos, preferencias y entorno del usuario, eliminando la necesidad de repetir el contexto de trabajo en cada sesión.

3. **Subagentes independientes de vida corta:** Para resolver tareas complejas de forma limpia y económica, Hermes puede desplegar pequeños subagentes autónomos especializados con contextos muy acotados. Esto reduce drásticamente el consumo de tokens y permite el uso eficiente de modelos de lenguaje más pequeños y locales.

4. **Omnipresencia y control multiplataforma:** Como demonio siempre activo, puede conectarse a más de 20 plataformas de mensajería (Telegram, WhatsApp, Slack, Teams) para ofrecer una interacción consistente desde la terminal o el teléfono celular.

5. **Valor estratégico para la gestión pública:** Su naturaleza 100% de código abierto e instalable de forma local garantiza la soberanía tecnológica y privacidad de datos del Estado, reduce costos de tokens al correr con modelos pequeños optimizados (como Qwen 3.6 o Gemma 4) y permite programar tareas automatizadas de fiscalización o auditoría 24/7 sin enviar datos sensibles a servidores de corporaciones extranjeras.

## ¿Cómo funciona?

El funcionamiento técnico de Hermes se sostiene sobre cuatro pilares fundamentales:

1.  **Bucle de aprendizaje y habilidades auto-evolutivas (*Self-Evolving Skills*):** Cuando el agente se enfrenta a una tarea compleja o recibe retroalimentación correctiva, es capaz de escribir y refinar de forma autónoma sus propios procedimientos de resolución de problemas. Estas "habilidades" se guardan en archivos de instrucciones (`SKILL.md`) bajo el estándar abierto `agentskills.io` y se cargan dinámicamente cuando el sistema detecta que son necesarias para una tarea.

2.  **Memoria persistente estructurada:** El agente utiliza una base de datos SQLite local para almacenar hechos clave sobre el entorno de trabajo, las preferencias del usuario y los proyectos en curso (mediante los archivos `MEMORY.md` y `USER.md`). Cuenta con un motor de búsqueda de texto completo que le permite recuperar contextos de conversaciones pasadas de manera instantánea.

3.  **Subagentes contenidos (*Contained Sub-agents*):** Para evitar sobrecargar la ventana de contexto de los modelos de lenguaje (lo que provocaría olvidos o un uso ineficiente de recursos), Hermes delega tareas secundarias complejas (como búsquedas en la web o edición de archivos) a pequeños "subagentes trabajadores" de vida corta con herramientas y contextos muy acotados. Esto reduce el consumo de tokens y permite utilizar modelos locales de menor tamaño de forma altamente confiable.

4.  **Pasarela de mensajería unificada (*Unified Gateway*):** Hermes se ejecuta en segundo plano como un demonio y se conecta con más de 20 plataformas de comunicación (Telegram, Discord, WhatsApp, Slack, Signal, Microsoft Teams, etc.). Esto permite interactuar con el mismo agente y mantener el hilo de la conversación de forma consistente desde una terminal de computadora o desde un teléfono móvil.

### ¿Uso en la gestión pública?

La arquitectura de Hermes se alinea de forma directa con los requerimientos de **gobernanza, eficiencia y seguridad** del Estado, ofreciendo soluciones prácticas a las barreras tradicionales de adopción de la IA en la administración pública:

*   **Garantía de Soberanía Tecnológica y Privacidad de Datos:** Al ser 100% de código abierto, un organismo público puede desplegar a Hermes localmente (*on-premises*) o en servidores internos utilizando entornos como Ollama. Al emparejarse con modelos de pesos abiertos de alta eficiencia y tamaño moderado (como las series Qwen o Gemma), la institución puede procesar información gubernamental altamente sensible y datos personales de la ciudadanía sin necesidad de enviarlos a servidores de empresas tecnológicas extranjeras.

*   **Preservación de la Memoria Institucional:** En la gestión pública, la rotación o jubilación de personal calificado suele provocar pérdidas graves de conocimiento operativo. Hermes permite mitigar esto registrando los flujos de trabajo burocráticos que los funcionarios experimentados le enseñan, consolidándolos como "habilidades institucionales" permanentes en su catálogo de consulta.

*   **Auditoría y Fiscalización Automatizada (Tareas Cron):** Utilizando su gestor integrado de automatizaciones (programación de tareas desatendidas), el agente puede monitorear de forma continua registros de transacciones públicas (como portales de licitaciones o ChileCompra) en tiempo real, identificar señales de alerta o anomalías estadísticas y notificar de inmediato a los equipos de auditoría a través de sus canales de comunicación habituales en Teams, Slack o Signal.

*   **Atención Ciudadana Omnicanal y Lenguaje Claro:** Mediante su integración nativa con WhatsApp o Telegram, Hermes puede actuar como un asistente ciudadano inteligente capaz de guiar a los usuarios en trámites complejos, resolver dudas frecuentes y traducir la jerga jurídica y administrativa difícil a un lenguaje sencillo y accesible.

*   **Eficiencia Presupuestaria y Reducción de Costos:** Al segmentar problemas complejos mediante subagentes contenidos y permitir el uso de modelos locales medianos altamente capaces, Hermes optimiza radicalmente el consumo computacional, disminuyendo significativamente la dependencia de costosos tokens de APIs propietarias.

## Guía técnica de instalación

**Configuración Local de Hermes Agent conectado a Telegram con Enfoque de Seguridad**

La adopción de **Hermes Agent** en las instituciones públicas puede representar un paso estratégico hacia la **soberanía tecnológica** y el control democrático de la información. Al ser un desarrollo 100% de código abierto bajo licencia MIT, permite el despliegue de un asistente cognitivo persistente en servidores propios o locales, garantizando que los datos de la ciudadanía y del Estado nunca salgan de la infraestructura institucional. Esto aplica para cualquer agente con caracterísicas similares a Hermes.

A diferencia de los chatbots tradicionales de "un solo turno", Hermes opera como un servicio persistente (*daemon*) que almacena su memoria en una base de datos SQLite local, aprende de cada sesión, gestiona flujos complejos a través de subagentes y es capaz de auto-generar habilidades reutilizables.

---

### Requerimientos Previos

Antes de iniciar la instalación, asegúrese de contar con las siguientes condiciones técnicas y de seguridad:

1.  **Entorno de Ejecución:** Una máquina con Linux, macOS o Windows (WSL2 o nativo).

2.  **Hardware de Cómputo Local (Inferencia de IA):** Para ejecutar modelos locales de alto rendimiento (clase 27B a 35B parámetros como Qwen o Gemma) sin consumo de tokens externos, se recomienda contar con tarjetas gráficas dedicadas (como las GPUs de clase empresarial o consumo aceleradas por hardware NVIDIA) que reduzcan la latencia de procesamiento.

3.  **Docker Instalado:** Habilitar Docker es un requisito indispensable de ciberseguridad para garantizar el aislamiento de procesos (*sandboxing*) ante la ejecución de código o comandos por parte del agente.

4.  **Cuenta de Telegram:** Para crear el bot de acceso institucional.

---

### 1. Instalación
**Instalación de Hermes Agent**

El proceso de instalación de Hermes Agent está automatizado mediante un script que descarga los recursos e instala de forma aislada sus dependencias internas utilizando el gestor de paquetes de alto rendimiento **uv**.

#### En Linux, macOS o Windows Subsystem for Linux (WSL2):
Abra su terminal y ejecute el siguiente comando de descarga directa:
```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

#### En Windows (PowerShell nativo, sin WSL):
Ejecute el instalador de PowerShell:
```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```
*Nota técnica: El instalador de Windows configura automáticamente un entorno aislado con Python, Node.js y una terminal portátil Git Bash (MinGit) sin necesidad de permisos de administrador.*

#### Recargar la consola:
Una vez finalizado el script, recargue su terminal para activar las variables de entorno:
```bash
source ~/.bashrc  # o source ~/.zshrc en macOS
```

---

### 2. Despliegue del Modelo
**Despliegue del Modelo de Lenguaje Local (Ollama)**

Para salvaguardar la privacidad de la información institucional, se debe evitar el uso de APIs externas de "caja negra". Desplegaremos un modelo de lenguaje local utilizando **Ollama**.

1.  **Instale y ejecute Ollama** en el servidor o computadora local.
2.  **Descargue un modelo optimizado** para el uso de agentes. La serie de modelos de pesos abiertos Qwen (como `qwen2.5:32b` o similar) o Gemma ofrecen una excelente precisión en la comprensión de directrices técnicas complejas y en el uso de herramientas. Ejecute en su consola:
    ```bash
    ollama run qwen2.5:32b
    ```
3.  **Vincule Hermes con el modelo local:** Ejecute el comando interactivo de configuración de modelos en la terminal del agente:
    ```bash
    hermes model
    ```
    Seleccione la opción de proveedor **Ollama** e indique el modelo descargado. Esto configurará el archivo `~/.hermes/config.yaml` con el endpoint de inferencia local.

---

### 3. Creación del Bot
**Creación y Vinculación del Bot de Telegram**

La pasarela de mensajería de Hermes (*Messaging Gateway*) permite interactuar con el agente y mantener la continuidad de las conversaciones directamente desde el teléfono inteligente.

1.  **Crear el Bot:** 
    *   En la aplicación de Telegram, busque al usuario oficial `@BotFather`.
    *   Inicie la conversación y envíe el comando `/newbot`.
    *   Siga las instrucciones para asignarle un nombre y un nombre de usuario institucional a su bot.
    *   **Guarde de manera segura el Token de la API de Telegram** proporcionado (ej. `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ`).
2.  **Configurar la pasarela de mensajería:**
    Ejecute el asistente interactivo de configuración de canales de mensajería en la terminal de su servidor:
    ```bash
    hermes gateway setup
    ```
    El asistente le solicitará seleccionar la plataforma (elija **Telegram**) e introducir el Token de API que generó con el `@BotFather`. Este secreto quedará guardado en el archivo de entorno seguro en `~/.hermes/.env`.

---

### 4. Configuración de Seguridad
**Configuración de Seguridad y Aislamiento (Sandboxing)**

**Este es el paso más crítico para un despliegue seguro en una red institucional.** Dado que Hermes puede ejecutar comandos de consola e interactuar con el sistema de archivos, permitir su ejecución directa en la máquina anfitriona puede abrir graves vulnerabilidades de ciberseguridad ante inyecciones indirectas de prompts o ejecución de código malicioso.

Aplique de forma obligatoria las siguientes tres políticas de seguridad:

#### 1. Activar el Aislamiento de Terminal en Docker
Establezca que todas las acciones del terminal que ejecute el agente se realicen dentro de un contenedor Docker aislado y seguro, evitando la alteración del sistema operativo anfitrión:
```bash
hermes config set terminal.backend docker
```

#### 2. Bloquear el Acceso Abierto en Mensajería
Abra el archivo de entorno local de configuración de secretos con su editor de preferencia (el archivo se ubica en `~/.hermes/.env` o en la ruta `%LOCALAPPDATA%\hermes\.env` en Windows nativo).

Asegúrese de configurar la siguiente directriz de seguridad para evitar que cualquier usuario externo en internet pueda hablar con el bot institucional de su equipo y acceder a la consola del servidor:
```env
GATEWAY_ALLOW_ALL_USERS=false
```

#### 3. Habilitar la Autenticación Segura de Equipos (DM Pairing)
Para autorizar a los miembros de su equipo de desarrollo o gestión sin gestionar manualmente listas complejas de IDs de usuario, Hermes incorpora un sistema seguro de vinculación interactiva.
*   Cuando un miembro del equipo intente enviar un mensaje al bot de Telegram por primera vez, el sistema de mensajería de Hermes rechazará la interacción y generará un **código de un solo uso** en la consola del servidor.
*   El administrador del sistema, visualizando la consola, podrá validar y aprobar el código de emparejamiento, otorgando acceso selectivo únicamente al personal autorizado.

---

### 5. Puesta en Marcha
**Puesta en Marcha y Pruebas de Funcionamiento**

Una vez configuradas las directrices de seguridad y los modelos, proceda a inicializar el sistema.

1.  **Iniciar la pasarela de Telegram:** Ejecute el demonio persistente de mensajería en segundo plano:
    ```bash
    hermes gateway start
    ```
2.  **Prueba de verificación:**
    *   Abra Telegram en su dispositivo móvil y busque su bot.
    *   Envíe un mensaje de saludo inicial (ej: `Hola`).
    *   El bot le solicitará el proceso de emparejamiento interactivo. Valide el código desde la consola del servidor.
    *   Una vez emparejado, póngalo a prueba pidiéndole que ejecute una tarea de desarrollo o análisis, como:
        > *"Escribe una función de Python para validar un RUT o formato de identificación de mi país y pruébala"*
    *   Verifique en la consola del servidor cómo el agente inicia el contenedor Docker para compilar y probar la rutina de forma segura.

---

### Buenas Prácticas
**Buenas Prácticas para la Experimentación del Equipo**

*   **Defina el Contexto Institucional:** Guarde un archivo llamado `AGENTS.md` o `.hermes.md` en el directorio de trabajo del equipo. Este archivo debe detallar las convenciones técnicas de su organización (ej: *"Utilizamos PostgreSQL como base de datos y Python 3.11"*), garantizando que el agente las asimile automáticamente en cada sesión.
*   **Gestione el Espacio de Memoria:** Si las sesiones de experimentación se vuelven muy extensas o lentas, controle el consumo enviando el comando `/compress` desde el chat de Telegram para consolidar el historial conversacional.
*   **Evolución del Agente:** Si el bot realiza un procedimiento complejo de varios pasos que su equipo planea repetir con frecuencia, ordénele lo siguiente desde la interfaz de chat:
    > *"Guarda este procedimiento como una habilidad llamada [nombre-de-la-tarea]"*
    
    A partir de ese momento, la rutina quedará inmortalizada en el catálogo local de habilidades bajo el estándar de código abierto `agentskills.io` y podrá ser ejecutada de forma desatendida mediante tareas programadas (cron).
